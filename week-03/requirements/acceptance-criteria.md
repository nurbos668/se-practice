# Acceptance criteria — three selected stories

Assumptions first, then the criteria. Each block names the story it belongs to. 3 to 5 criteria per
story, every one in Given / When / Then form, and every set covers a validation or error case — not
three happy paths.

---

## Assumptions

These must settle the two questions the scenario leaves open. Either answer is accepted; no answer
is not.

- **Overlap:** a booking that ends exactly when another begins is **allowed** (not an overlap) under R3, because the interval is treated as half-open [start, end) — the room becomes free the instant the earlier booking ends.
- **Duration:** a booking of exactly two hours is **allowed** under R2, because "at most two hours" is read as a ≤ two-hour ceiling, not a strict less-than.
- A room's blocked/available status and its existing bookings are independent: blocking a room does not cancel bookings already made before the block.
- Confirmations and rejections are generated by the system itself immediately after the triggering action; no external notification channel is involved.

## US-02 — Book a room

### AC-01
- **Given** a room is free for the requested slot and the slot starts in the future
- **When** the student submits a booking for that slot
- **Then** the booking is created and the room is no longer free for that slot

### AC-02
- **Given** the student selects a start time earlier than the current time
- **When** they submit the booking
- **Then** the system rejects the booking for starting in the past

### AC-03
- **Given** the student requests a duration of exactly two hours
- **When** they submit the booking
- **Then** the booking is accepted, and a request for two hours and one minute is rejected for exceeding the maximum duration

### AC-04
- **Given** an existing booking occupies a room from 10:00 to 11:00
- **When** the student requests 10:30 to 11:30 for the same room
- **Then** the system rejects the booking as overlapping

### AC-05
- **Given** an existing booking occupies a room from 10:00 to 11:00
- **When** the student requests 11:00 to 12:00 for the same room
- **Then** the booking is accepted, because the two slots do not overlap

---

## US-03 — Cancel a booking

### AC-06
- **Given** the student has a future booking they created
- **When** they cancel it before its start time
- **Then** the booking is removed and the room becomes free for that slot

### AC-07
- **Given** a booking belongs to a different student
- **When** the student attempts to cancel it
- **Then** the system rejects the cancellation

### AC-08
- **Given** a booking's start time has already passed
- **When** the student attempts to cancel it
- **Then** the system rejects the cancellation

---

## US-06 — Block a room

### AC-09
- **Given** a room is currently available and has no future bookings
- **When** the administrator blocks the room
- **Then** the room's status changes to blocked

### AC-10
- **Given** a room has an existing future booking
- **When** the administrator blocks the room
- **Then** the room's status changes to blocked and the existing booking remains unchanged

### AC-11
- **Given** a room is blocked
- **When** a student attempts to book that room
- **Then** the system rejects the booking
